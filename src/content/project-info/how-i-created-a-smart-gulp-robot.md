# Как я создал умного Gulp робота

_Дата публикации: 2026-06-07_

Привет! Начни писать текст новой статьи прямо здесь в формате Markdown...

Каждый веб-разработчик рано или поздно приходит к мысли, что рутина убивает творчество. Когда я начинал делать свой сайт-портфолио, я хотел просто писать код и делиться мыслями в блоге. Но реальность оказалась суровее: сломанные пути на хостинге, капризы серверов GitHub Pages, постоянная ручная правка ссылок в меню и бесконечный ручной деплой.

В этой статье я расскажу, как я прошёл путь от ручного копирования файлов сборки до создания автономной экосистемы на Gulp 5 и Node.js, которая сама переводит заголовки, генерирует страницы и управляет навигацией.

---

## Проблема №1: Капризы GitHub Pages и PurgeCSS

Первый серьёзный бой случился, когда я выложил сайт на GitHub Pages. На локальном компьютере (через Live Server) всё выглядело идеально, но в сети сайт открывался абсолютно «голым» — без стилей и дизайна.

Причин оказалось сразу две:

1. **Точки в путях (`./css/...`)**: GitHub Pages некорректно обрабатывает относительные пути, если пользователь заходит по ссылке без слэша на конце. Браузер просто терял папку репозитория.
2. **Агрессивный PurgeCSS**: Мой плагин для очистки неиспользуемого CSS на продакшене работал слишком хорошо. Он сканировал разметку и просто вырезал все стили моих БЭМ-компонентов (`.about-me`, `.projects-grid`, `.footer`), посчитав их лишними.

### Как это было решено:

Я полностью переписал логику тасков. В HTML-таск я добавил кастомный стрим трансформации через `Transform`, который при сборке продакшена автоматически очищает пути от точек. А в PurgeCSS я настроил универсальный RegExp-фильтр (`safelist.deep: [/^[a-zA-Z]/]`), который автоматически защищает любые БЭМ-классы, независимо от того, сколько новых страниц появится на сайте.

## Проблема №2: Сломанные ссылки в подпапках блога

Когда я добавил генерацию статей из Markdown, навигация окончательно запуталась. Находясь внутри статьи (в подпапке `/blog/`), ссылки главного меню («Проекты», «Обо мне») вели в никуда, выдавая ошибку 404. Браузер пытался искать якоря прямо внутри папки блога.

Писать пути вручную для каждой страницы — это плохой тон и путь к багам. Поэтому я внедрил **динамическую автоматизацию навигации** прямо в свой `gulpfile.js`.

Теперь робот сам заглядывает в `gulp.config.js`, берёт оттуда имя репозитория (`repoName: "portfolio"`) и на лету подставляет его во все ссылки меню. Если завтра я переименую репозиторий или перенесу сайт на платный хостинг, мне достаточно будет изменить всего одно слово в конфиге — и весь сайт пересоберётся сам!

## Финал: Создание умного CLI-генератора с ИИ-переводчиком

Самой крутой частью работы стало создание собственного консольного робота для написания статей. Мне не хотелось вручную создавать `.md` файлы, думать, как перевести заголовок для красивого URL-адреса, и руками вписывать ссылки в сайдбар.

Я написал скрипт `create-post.js` на Node.js с интеграцией API переводчика Google.

## Как это работает теперь:

1. Я запускаю в терминале всего одну команду: `npm run create-post`.
2. Робот спрашивает название статьи на русском языке. Я пишу: _«Как я создал умного Gulp робота»_.
3. **За долю секунды скрипт делает всю рутину за меня:**
   - Переводит фразу на чистый английский смысл: _«How I created a smart Gulp robot»_.
   - Генерирует идеальный системный файл: `how-i-created-a-smart-gulp-robot.md`.
   - Внутри файла автоматически проставляет дату и заголовок `#`.
   - Сам лезет в код компонента `blog-sidebar.html` и встраивает туда готовую БЭМ-ссылку (файл на английском, а текст для людей — на русском!).

Бонусом я написал TypeScript-модуль для самого сайдбара: когда пользователь читает статью, скрипт находит её в списке справа, подсвечивает фиолетовым цветом и намертво блокирует от повторных кликов через `pointer-events: none`.

## Заключение

Теперь мой рабочий процесс выглядит как у профессионального контент-мейкера:

```bash
# 1. Создаю статью (ввожу название на русском)
npm run create-post

# 2. Пишу текст в удобном Markdown-файле

# 3. Собираю и публикую на хостинг одной связкой команд
npm run clean && npm run build && npm run deploy
```

Автоматизация — это не про экономию пяти минут. Это про то, чтобы развязать себе руки и сфокусироваться на главном: написании качественного кода и крутых статей. Будьте ленивыми разработчиками, автоматизируйте рутину!
