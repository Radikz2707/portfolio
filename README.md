# 🚀 Gulp + TypeScript Professional Engine (v3.1 - Premium Edition)

Современный, сверхбыстрый и полностью автоматизированный кастомный движок для профессиональной модульной веб-разработки. Построен на строгом компонентном подходе (БЭМ-компоненты как изолированные экосистемы «Plug and Play») с использованием Gulp 5, Webpack 5, строгого TypeScript и плоской конфигурации ESLint v10.

---

## 🛠️ Быстрый старт (Развертывание и Разработка)

Чтобы запустить проект или развернуть окружение, выполните следующие команды в терминале:

1. **Установите зависимости** через стабильное зеркало с автоматическим разрешением конфликтов peer-зависимостей линтера:
   ```bash
   npm install --registry=https://npmmirror.com --legacy-peer-deps
   ```
2. **Инициализируйте структуру** папок (Header-Main-Footer):
   ```bash
   npm run init
   ```
3. **Запустите сервер разработки** (с вотчерами и автооткрытием браузера):
   ```bash
   npm run dev
   ```

## 🧱 Встроенный CLI-конструктор компонентов

Больше не нужно вручную создавать файлы и прописывать импорты — используйте короткие команды автоматизации:

* **Создать БЛОК (компонент страницы):**
  ```bash
  npm run create ---имя_блока
  ```
  Генерирует HTML/SCSS/TS в `src/components/` и жестко подключает в точки входа. Идеал для каркаса сайта (например: `header`, `hero`, `services`).

* **Создать МОДУЛЬ (в ленивом асинхронном режиме):**
  ```bash
  npm run module ---имя_модуля
  ```
  Генерирует SCSS/TS в структуре `src/js/modules/` и подключает в `app.ts` через динамический `import()`. Код подгрузится автоматически только тогда, когда на странице появится элемент с соответствующим классом. Идеал для тяжелой логики (`slider`, `modals`, `tabs`).

* **Создать ПЛАГИН (расширение функционала):**
  ```bash
  npm run plugin ---имя_плагина
  ```
  Генерирует SCSS/TS в структуре `src/js/plugins/` и подключает в `app.ts`. Идеал для кастомных библиотек (`form-validator`, `lazy-loader`, `analytics`).

* **Универсальное УДАЛЕНИЕ:**
  ```bash
  npm run remove ---имя_элемента
  ```
  Универсальный деструктор. Физически удаляет папки/файлы и полностью вырезает все регулярные выражения импортов и вызовов, не ломая форматирование. Снабжён массивом `PROTECTED_NAMES` для защиты системных директорий от случайного стирания.

## 🔥 Улучшенные технологические особенности v3.1

### 💎 Качество кода, Тестирование и Безопасность
* **Интеграция с Telegram API:** Форма контактов полностью функциональна. Сообщения отправляются напрямую в Telegram через защищенный механизм. Ключи доступа (`TOKEN`, `CHAT_ID`) хранятся в `.env` и автоматически инжектируются в проект при сборке через кастомный Gulp-генератор `env-config.js`.
* **Unit-тестирование (Vitest + JSDOM):** В проект внедрена современная система тестов. Проверяется как логика UI-компонентов (модалки, меню, валидация контактов), так и системные утилиты сборщика. Тесты запускаются автоматически перед каждым билдом.* **TypeScript Strict & Webpack 5:** Полная поддержка компиляции, строгая проверка типов (`strict: true`) и изоляция модулей для бесперебойной работы.* **Modern ESLint & Stylelint:** Автоисправление (`--fix`) измененного файла происходит прямо при сохранении, выводя цветные отчеты в консоль. CSS-свойства строго сортируются по логическим группам (Recess-порядок).
* **Pre-commit хуки (Husky v10 + lint-staged):** Полная автоматизация контроля качества. При каждой команде `git commit` система автоматически запускает линтеры за доли секунды и проверяет только измененные файлы.
* **Умная защита авторских прав от скачивания:** Во фронтенд-слой внедрён интеллектуальный скрипт защиты интеллектуальной собственности. Он полностью блокирует вызов контекстного меню, клавишу `F12`, а также комбинации `Ctrl+U` (просмотр кода) и `Ctrl+S` (скачивание сайта). Снабжён **страховкой окружения**: на локальном сервере разработки (`localhost`) защита автоматически отключается для удобства дебага, активируясь только в продакшене.

### 🖼️ Работа с графикой, контентом и шрифтами
* **Процессор контента на Node.js (`content-processor.js`):** Реализован концепт **Data-Driven**. Разработчик пишет статьи в папке контента в форматах Markdown (`.md`) или Microsoft Word (`.docx`). Кастомный асинхронный процессор на базе `through2` и `mammoth` на лету конвертирует файлы, очищает мусорные теги Word, выстраивает иерархию заголовков `H1/H2` и нативно инклудит мастер-шаблон. **Безопасность:** Процессор автоматически экранирует блоки кода и корректирует пути к изображениям, что подтверждено Unit-тестами.
* **Smart WebP Cache & SVG Спрайты:** Автоматическая генерация `.webp`. Плагин `newer` сопоставляет базовые имена файлов, благодаря чему картинки не пережимаются заново при перезапуске сервера. SVG-иконки нативно очищаются от лишних атрибутов через SVGO-трансформатор во время сборки в спрайт.
* **PWA Favicons:** Защищенный таск автоматической генерации полного адаптивного набора иконок (Apple, Android, браузеры) и манифестов из одного файла `favicon.png`.
* **Авто-шрифты:** Сборщик автоматически конвертирует исходные `.ttf/.otf` файлы в облегченный формат `.woff2` и сам генерирует файл подключения `_fonts.scss` со всеми начертаниями.

### 🏗️ Архитектура, Системные Алиасы и Роутинг
Для чистых импортов без бесконечных цепочек `../../` настроены системные алиасы путей в `tsconfig.json` и Webpack:
* `@/*` — указывает на корень скриптов `src/js/`
* `@comp/*` — указывает на папку компонентов `src/components/`
* `@modules/*` — указывает на папку логических модулей `src/js/modules/`
* `@plugins/*` — папка `src/js/plugins/` для кастомных локальных библиотек
* **Кросс-страничный роутинг без ошибок `Cannot GET`:** Локальный сервер `BrowserSync` перенастроен с базового пути `@file` на виртуальный роутинг репозитория (`/portfolio/`). Это полностью ликвидировало проблему многостраничной вложенности: якорные ссылки, плавный скролл и переходы между статьями блога и главной страницей работают безбагово как на локальном компьютере, так и на серверах GitHub Pages.
